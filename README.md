## Overview

This project designs, implements, and evaluates a multi-GPU pipeline architecture for real-time digital inline holography (DIH) particle reconstruction on a 1–4 GPU workstation. The pipeline consists of six computational stages: image resize, EMA enhancement, angular spectrum propagation, CNN-based particle detection, ML classification, and post-processing.

Three implementations of the angular spectrum propagation kernel are provided:

| Implementation | Backend | Location |
|---|---|---|
| Python (PyTorch) | torch.fft | `Scripts/holographic_reconstruction.py` |
| CUDA C++ | cuFFT | `cpp_cuda/src/holographic_reconstruction.cu` |
| OpenMP C++ | FFTW3f | `cpp_cuda/src/cpu_baseline.cpp` |

## End-to-End Pipeline

The full pipeline processes hologram images through 6 stages:

```
Stage 1 (CPU):  Load & resize JPEG → 448×448 grayscale
Stage 2 (GPU):  EMA background subtraction → enhanced frame [0,1]
Stage 3 (GPU):  Holographic reconstruction (3-plane, cuFFT) → [3,448,448] intensity
Stage 4 (GPU):  ImageNet normalize → TRT heatmap inference → NMS peak detection
Stage 5 (GPU):  Crop extraction → TRT classification → EC/PD labels
Stage 6 (CPU):  Static centerpoint filter → filtered detections
```

Two implementations are available:

| Implementation | Backend | Typical FPS |
|---|---|---|
| Python (`Scripts/pipeline.py`) | PyTorch + TRT (via torch_tensorrt / ultralytics) | ~99 FPS |
| C++ (`benchmark_pipeline`) | Native C++ + CUDA + TRT 10.x API | ~152 FPS |

### TensorRT Engine Setup

The C++ pipeline requires native `.engine` files (not torch_tensorrt `.ts` files). Build them from ONNX:

**Step 1: Export ONNX models (if not already present)**

```bash
cd /path/to/CSCI8205

# Export heatmap model to ONNX (uses legacy exporter for TRT compatibility)
python3 -c "
import torch, sys; sys.path.insert(0, 'Scripts')
from heatmap_model import load_heatmap_detector
model = load_heatmap_detector('Ref/CurrentPipelineCodes/inference/fast_bacteria_hm_optimized.pt', 'cuda')
dummy = torch.randn(1, 3, 448, 448, device='cuda')
torch.onnx.export(model, dummy, 'Ref/CurrentPipelineCodes/inference/heatmap_448.onnx',
    input_names=['input'], output_names=['output'],
    dynamic_axes={'input': {0: 'batch'}, 'output': {0: 'batch'}},
    opset_version=13, dynamo=False)
"

# Classifier ONNX should already exist at:
# Ref/CurrentPipelineCodes/inference/bacteria_class.onnx
```

**Step 2: Build TRT engines with dynamic batch (Python TensorRT API)**

```bash
python3 << 'EOF'
import tensorrt as trt

def build_engine(onnx_path, engine_path, input_name, min_shape, opt_shape, max_shape):
    logger = trt.Logger(trt.Logger.WARNING)
    builder = trt.Builder(logger)
    network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
    parser = trt.OnnxParser(network, logger)
    with open(onnx_path, "rb") as f:
        parser.parse(f.read())
    config = builder.create_builder_config()
    config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 4 << 30)
    config.builder_optimization_level = 4
    profile = builder.create_optimization_profile()
    profile.set_shape(input_name, min_shape, opt_shape, max_shape)
    config.add_optimization_profile(profile)
    print(f"Building {engine_path}...")
    engine_bytes = builder.build_serialized_network(network, config)
    with open(engine_path, "wb") as f:
        f.write(bytes(engine_bytes))
    print(f"  Saved ({len(bytes(engine_bytes))} bytes)")

# Heatmap: input [B,3,448,448] → output [B,1,112,112]
build_engine(
    "Ref/CurrentPipelineCodes/inference/heatmap_448.onnx",
    "Ref/CurrentPipelineCodes/inference/heatmap_448_dynamic.engine",
    "input", (1,3,448,448), (1,3,448,448), (32,3,448,448))

# Classifier: input [B,3,128,128] → output [B,2]
build_engine(
    "Ref/CurrentPipelineCodes/inference/bacteria_class.onnx",
    "Ref/CurrentPipelineCodes/inference/bacteria_class_dynamic.engine",
    "images", (1,3,128,128), (16,3,128,128), (32,3,128,128))
EOF
```

> **Note:** Engine files are platform-specific (GPU architecture + TRT version). You must rebuild them if you change GPUs or update TensorRT.

## Algorithm

All three implementations compute Fresnel propagation via the angular spectrum method:

```
1. Pad hologram with median background
2. Forward 2D FFT
3. For each depth plane z_k:
   a. Multiply spectrum by propagation filter: exp(-2πj·z_k·√(1-(λf/r)²)/λ)
4. Batched inverse 2D FFT
5. Phase correction: result *= exp(2πj·z_k/λ)
6. Intensity: |result|²
7. Min-max normalize to [0,1] with background shift scaling
```

### CUDA kernel architecture

The CUDA implementation uses 5 specialized kernels plus cuFFT:

1. **`pad_hologram_kernel`** — Pads input, stores as complex. Median computed via thrust::sort.
2. **`build_propagation_filter_kernel`** — Precomputes f2_new array in DFT order (run once per image size).
3. **`apply_propagation_and_broadcast_kernel`** — Multiplies FFT result by exp filter for all depth planes simultaneously.
4. **`phase_correction_and_intensity_kernel`** — Phase correct, compute |result|², remove padding.
5. **`normalize_intensity_kernel`** + **`apply_shift_scaling_kernel`** — Global min/max reduction (via thrust), normalize, clamp.

The forward FFT uses a single `cufftPlan2d`. The inverse FFT uses `cufftPlanMany` to batch all depth planes in one call.

## Performance

### Reconstruction Only (RTX 5090, 256×256, 3 planes)

| Implementation | Latency | Throughput |
|---|---|---|
| CUDA C++ (cuFFT) | 0.22 ms | 4,584 ops/s |
| OpenMP C++ (FFTW, 4 threads) | 2.65 ms | 377 ops/s |
| PyTorch GPU (Single GPU) | 0.60 ms | 1,678 ops/s |
| PyTorch CPU (Single CPU) | 1.40 ms | 714 ops/s |

### End-to-End Pipeline (RTX 5090, 448×448, 100 images)

| Implementation | E2E Latency | FPS | Classification | Heatmap | Reconstruction |
|---|---|---|---|---|---|
| C++ TRT | 6.59 ms | **152** | 1.37 ms | 0.46 ms | 0.17 ms |
| Python TRT | 10.07 ms | 99 | 8.11 ms | 1.27 ms | 0.34 ms |

The C++ pipeline achieves a **1.53× speedup** end-to-end, with the biggest gains in classification (5.9× faster using native TRT C++ API vs ultralytics YOLO wrapper).
